# EFI Forge v0.1.11 全链路改进范围

## 背景

EFI Forge 面向硬件组合复杂、资料不完整、可能无法直接安装 macOS 的 Windows 用户。项目目标不是宣称每台电脑都能一键成功，而是在不夺走用户选择权的前提下，尽可能准确地扫描硬件、解释风险、生成或融合候选 EFI，并把结构与数据安全作为强制边界。

当前公开版仍是 v0.1.10 Alpha；本文描述的是本地 v0.1.11 开发候选，不代表已经发布。

## 不可改变的产品边界

- 信息不足：给出证据缺口和补充方法，允许继续。
- 硬件可能不兼容：降低可信度、保留高风险提示，允许继续实验。
- EFI 结构损坏、组件完整性失败或 `ocvalidate` 失败：停止复制和安装路径。
- 目标目录非空、路径越界或可能破坏用户数据：停止。
- 规则、社区仓库和 `ocvalidate` 均不能替代真机启动、Recovery、安装和安装后验证。

## 本轮问题定义

1. “规则覆盖率”容易被误读为安装成功率。
2. 自动模板未覆盖旧平台、OEM、小众笔记本或混搭硬件时，用户看不到清晰的替代路径。
3. 缺少整机型号、主板型号、BIOS、PCI ID 或 Subsystem ID 时，界面只显示低可信度，缺少可执行的证据补充清单。
4. 移动窄屏的四步流程导航需要全部可见，不能依赖隐藏的横向滚动。
5. 组装页必须根据自动候选与手动组件模式显示不同指引，不能把组件暂存包描述成可启动 EFI。

## 实施要求

### 兼容判断

- 保留现有 `coverage` 数据字段，用户界面统一称为“规则识别度”。
- 每次显示识别度时同时说明“不是安装成功率或实机验证结论”。
- 兼容结论与软件工作流就绪度分开呈现。

### 继续路径

兼容判断页始终展示三条用户可控路径：

1. 审核平台：项目候选 EFI；未审核平台：官方组件暂存包。
2. 导入并检查用户已有的完整 EFI。
3. 按组件补充或替换 Kext、AML 与 UEFI Driver。

未收录型号不能关闭后两条路径，也不能因为硬件警告关闭下一步。

### 证据缺口

将下列情况聚合为非阻断清单：

- 整机厂商或完整型号不足；
- 主板型号、BIOS 版本或 BIOS 日期不足；
- ThinkPad 四位 Machine Type 缺失；
- 显卡、网络、音频或存储分类为空；
- 设备缺少直接 PCI 身份或 Subsystem ID。

每项必须包含影响说明和用户可以执行的补充动作。

### 组装指引

- 自动模板存在时，引导“生成候选 → 可选融合 → 校验 → 空目录复制”。
- 自动模板不存在时，引导“生成官方组件暂存包 → 提供 config.plist/完整 EFI → 校验 → 空目录复制”。
- 手动组件模式不得显示为工具推荐或自动适配。

## 验收标准

- 审核台式机显示自动候选路径，同时保留完整 EFI 与组件融合路径。
- ThinkPad、OEM 和未知平台显示手动组件路径，仍可进入组装。
- 缺失硬件证据只产生清单，不改变 `CompatibilityReport.canContinue`。
- 高风险 GPU/存储仍允许进入组装，但不出现“验证通过”或“保证可用”。
- 390px 窄屏无全局横向溢出，四个流程步骤全部可见。
- 前端单元测试、目录导入测试、TypeScript、生产构建、Rust 测试、格式检查和 Clippy 通过。
- 未经真实硬件验证，不提升 `verificationStage`，不发布新的 GitHub Release。

## 已实施的深层修补

- 从 CPUID leaf 1 取得真实 CPU Family/Model，避免直接使用 WMI 的通用值；同时保守识别 Rocket/Tiger/Alder/Raptor/Meteor Lake 与 AMD Zen 1–5。
- 增加通用 NVIDIA 现代 macOS 高风险规则、AMD Vega APU 手动 NootedRed 路径、SK hynix PC711 风险和 Tahoe Intel 无线/模拟音频专项警告。
- Tahoe 26 始终是手动研究目标，不自动生成 `config.plist`，不自动加入 AppleALC。
- `config.plist` 校验现在检查 OpenCore 顶层字典、Add 数组、启用项类型、Kext `PlistPath` 与不区分大小写的重复路径。
- 安全复制在暂存区完成后再次验证 EFI，并在实际复制期间重新强制文件数、容量和目录深度上限。
- 生成期间使用的 Windows 工具不保留在导出目录；完整候选也不保留临时源模板。
- 社区导入和运行时解析双重排除 `DONT USE THIS`、占位用户名和无效仓库名，旧快照也不会向用户展示这些链接。
- 程序内部语义从“可安装”收紧为“可复制”，并在第 4 步明确区分普通导出目录与真正可启动的 FAT32 EFI 分区。
