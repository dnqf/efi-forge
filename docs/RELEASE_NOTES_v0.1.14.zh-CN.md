# v0.1.14 Alpha · 身份、配置边界与验证证据修复

本轮是本地发布候选，不代表已上传或公开 GitHub Release。没有新增“保证可启动”的机型，也没有导入未经许可的社区整包。

## 已实现

- 社区审核匹配要求完整型号一致，避免 Z490-P 与 Z490-PRO 子串误判；缺少必需 ACPI 语义证据只能保留人工核对候选。
- 在整个来源注册表上检查重复 ID，拒绝空白身份条件；父控制器 PCI 身份不能满足具体设备的审核条件。
- 硬件指纹升级为 v3，使用结构化 JSON 编码，消除字段分隔符碰撞；缺失值与文字 `unknown` 区分，设备顺序仍不影响指纹。
- 已有 8086:9BC5 样本的身份识别集中到共用函数，避免 Windows 显示名称变成 Basic Display Adapter 后改变该候选的核显配置。其他未归一设备仍可能依赖名称线索，不能视为全 PCI 覆盖。
- 笔记本不会选择台式机预编译 ACPI、桌面 framebuffer、AMD 桌面固件开关和 MacPro 专属组件；用户仍可导出组件或使用自己的 EFI。
- 自动组装遵守可行性评估的手动路径，不再与 CPU 指令集风险结论矛盾。
- 真机验证的九个观察项默认全部为“未测试”，不再由所选阶段或结果自动填入通过/失败。安装后功能验证需要逐项证据，备注提示避免隐私内容。
- 提供统一的 workspace npm 检查/构建入口，并在脚本结束后恢复进程环境变量。

## 升级与边界

v2 指纹的历史证据保留原样，但不能自动绑定 v3 指纹；需要基于当前配置重新核对，不可直接改写旧证据哈希。旧的安装后证据如果缺少必要观察项，会被拒绝提升验证等级，原文件不被修改。

未知或可能不兼容硬件仍只警告；EFI 损坏、组件完整性失败、不安全路径、覆盖或数据损坏风险继续阻止操作。社区发现层不参与自动下载、可信度推荐或配置写入。

## 本轮未冒充完成的工作

没有真实目标电脑安装成功证明；没有代码签名证书；没有新增有授权且实机审核的社区整包。尚未将全部 PCI 分类、UI 操作状态和原生校验重构为单一状态机；也没有迁移安装后应用的系统临时缓存。

具体检查、安装包哈希和剩余验证项以本轮审查记录为准。
