# EFI Forge 产品需求文档

## 1. 产品定义

EFI Forge 是面向中文 OpenCore 初学者和维护者的 Windows 桌面候选 EFI 工作台。它读取目标电脑的脱敏硬件信息，用可追踪规则解释风险，并在本地组装、检查或融合 EFI 副本。

当前版本的“一键”边界是：对已审核平台下载哈希锁定的上游组件，生成候选 `config.plist`，检查 EFI 结构和引用，并运行同版本 `ocvalidate`。这只会产生候选 EFI，不会证明真机可启动或可安装。

工具目前不下载 Apple Recovery、不分区或格式化 U 盘、不制作完整 macOS 安装盘，也不会代替用户在 Recovery 中擦除目标磁盘。

## 2. 用户目标

1. 在改动 BIOS 或磁盘之前，看懂硬件的已知支持、风险和信息缺口。
2. 在“项目生成候选”、“自己的完整 EFI”、“安全融合副本”之间自由选择。
3. 得到来源、版本、哈希和规则可追踪的输出。
4. 不因误选路径覆盖现有 EFI 或其他用户文件。
5. 将 Picker、Recovery、安装和安装后结果以脱敏、精确绑定的证据返回工具。

## 3. v0.1.13 开发范围

### 已实现路径

- Windows 10/11 x64 只读硬件扫描与脱敏 JSON 导入/导出；schema v2 增加控制器、父 PCI 与笔记本 PnP 线索，旧 v1 报告继续兼容。
- Ventura 13、Sonoma 14、Sequoia 15 规则；Tahoe 26 只开放手动研究路径。
- 已审核 AMD Zen B450/B550 与 Intel Coffee Lake/Comet Lake 台式机候选生成。
- 新旧 Intel、AMD APU、ThinkPad 和 Legacy BIOS 手动/研究路由，不伪装成自动配置。
- NVIDIA、AMD GPU（含 RX 550 Lexa 区分）、网卡、独立蓝牙、音频和高风险 NVMe 的可追踪规则。
- VMD/RST/RAID、AHCI、NVMe、USB xHCI、Thunderbolt/USB4、Intel SST、I2C/PS2、电池、摄像头、指纹和读卡器证据账本；这些线索不会自动升级为“已支持”。
- DIY、OEM 台式机、ThinkPad、普通/AMD 笔记本、迷你机、工作站和旧平台分路由说明，不扩大未审核自动模板。
- 固定版本组件、下载上限、SHA-256、安全解压和同版本 `ocvalidate`。
- 完整 EFI 只读检查，以及 Kext、AML、UEFI Driver 显式选择和新目录融合。
- 只向空目录复制 `EFI`；复制前后重新检查，不覆盖、不格式化。
- ThinkPad 变体路由与 daliansky/Hackintosh 社区候选账本。社区链接只是未审核线索，不自动下载或参与 BuildPlan。

### 当前不宣称完成

- 任何平台的官方真机启动、Recovery、安装或安装后全功能认证。
- Apple Recovery 下载、完整安装介质制作、分区和格式化。
- 自动修改 BIOS、自动选择安装磁盘或自动登录 Apple 服务。
- 将社区索引视为已验证、可再分发或适配当前硬件的 EFI。
- 执行未经锁定版本、许可证和安全审核的社区二进制。

## 4. 不可破坏的安全原则

- 信息不足：显示未覆盖和证据缺口，降低可信度，允许继续。
- 硬件可能不兼容：显示高风险，不作推荐，保留实验和自有 EFI 路径。
- EFI 结构、锁定组件完整性或 `ocvalidate` 失败：停止当前输出或复制。
- 目标非空、路径互包含、符号链接/重解析点或可能破坏数据：停止。
- 不执行用户 EFI 或社区候选中的程序；只执行锁定来源和哈希的官方 OpenCore 工具。
- 不导出用户名、磁盘序列号、SMBIOS 序列号、MAC 地址、原始 PNP 实例路径或网络凭据。

## 5. 当前用户流程

```text
扫描本机 / 导入脱敏报告
  → 阅读硬件风险和规则识别度
  → 选择项目候选、官方组件暂存包或自有 EFI
  → 下载并校验锁定组件（如适用）
  → 生成 / 检查 / 融合到新目录
  → 结构与引用检查；受控候选额外运行同版本 ocvalidate
  → 复制到用户明确选择的空目录
  → 用户准备独立介质并测试 Picker / Recovery
  → 导出精确绑定的脱敏验证证据
```

## 6. 兼容结论语义

- `supported`：当前规则有明确处理路径，不等于整机已验证。
- `partial`：可继续，但需要选型、补丁、校准或真机验证。
- `blocked`：已知高风险或缺少关键能力；不推荐，但不剥夺实验权限。
- `unknown`：规则无法识别；记录证据缺口并降低可信度。

“规则识别度”的分母是当前报告中的检查对象；它不是硬件市场覆盖率、启动成功率或安装成功率。可信度等级只表达当前证据质量，不是成功承诺。

## 7. EFI 与规则来源

- OpenCore、Sample.plist、`ocvalidate`、`macserial`：Acidanthera/OpenCorePkg 固定 Release。
- Kext：对应官方项目的固定 Release。
- AMD 核心补丁：AMD-OSX/AMD_Vanilla 固定文件与哈希。
- ACPI：已审核预编译文件或用户明确选择的 DSDT/SSDT 路径。
- `config.plist`：由同版本 Sample.plist 在本地生成，或保留用户完整 EFI 的主来源配置。
- SMBIOS：受控候选由同版本 `macserial` 在本地产生，不导出到公共报告。
- 兼容规则：Dortania 指南、组件官方文档和项目审核记录。
- 社区候选：只保留最小事实索引和 GitHub 根链接，未审核、未下载、未执行。

## 8. 开发版验收标准

1. 演示/固定样本不能生成或导出可误用的真机 EFI 产物。
2. 已知规则在固定回归样本上产生稳定结论，未知组合不获得虚假精确匹配。
3. 信息不足和硬件高风险只警告；软件完整性、EFI 结构和数据安全问题才阻止。
4. 锁定组件的 URL、版本、大小、SHA-256 和规范文件名全部校验。
5. 生成和融合都在新暂存目录进行，失败不留可误用输出。
6. 安全复制仅接受空目录，并在暂存复制后重新检查 EFI。
7. 前端、导入器、TypeScript、Rust、Clippy 和格式检查全部通过。
8. 公开发布前另行完成 Windows 安装/启动/卸载冒烟测试，并明示未签名状态和 SHA-256。

## 9. 后续里程碑

1. 用更多真实脱敏报告扩充回归矩阵，但不用样本数量代替真机验证。
2. 建立按硬件指纹、BIOS 范围、config 哈希和验证阶段组织的可审核证据库。
3. 完成首批硬件的 Picker、Recovery、安装和安装后功能分级验证。
4. 在有独立权限边界、设备确认和可恢复方案后，再评估 Recovery 下载和安装介质制作。
5. 为公开稳定版建立 Authenticode 签名、Windows Defender 冒烟测试和发布证明流程。
