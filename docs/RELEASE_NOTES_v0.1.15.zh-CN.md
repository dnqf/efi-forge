# v0.1.15 Alpha · 可追溯输入、产物生命周期与缓存治理

v0.1.15 是预发布测试版。它改善 EFI Forge 的判断一致性、失败恢复和来源透明度，不代表所有电脑都能安装 macOS，也不把合成测试或社区链接描述为实机验证。

## 主要改进

- 统一 GPU 与网络设备的 PCI 身份分类，区分直接 PCI、父控制器、名称回退和用户提供；父 PCI、名称或手工值不能取得精确规则与自动配置资格。
- 建立可执行规则案例注册表。当前 22 个严格案例关联 18 条规则；另有 12 类、每类 3 个的合成配置矩阵，覆盖缺失信息和近似误判。剩余 23 条规则仍在审核清单中。
- 引入硬件输入、BuildPlan、EFI 产物、验证与复制的 revision/token 生命周期。切换硬件、目标系统或构建偏好会使旧产物失效，迟到任务不能覆盖新状态；取消和失败保留此前有效来源。
- 新增默认折叠的硬件补充入口，可补充整机、主板、BIOS 和 PCI 信息，并在当前会话恢复底稿或撤销。手工值导出时保留 `manualFields` 与 `user-provided` 来源，只作为人工研究线索。
- 新增可选运行时缓存位置。路径经过绝对路径、宽泛目录、源码/EFI 标记、符号链接和 Windows 重解析点检查；下载继续执行大小、SHA-256、唯一 `.part`、并发锁和低空间门禁。
- 组件下载与锁定版 `ocvalidate` 暂存共用版本化缓存服务。一次任务固定一个缓存根；切换只影响新任务，不迁移或删除旧缓存。
- 首次指南、警告继续、结构失败停止、融合回退和失败验证恢复改由可测试的 presentation/decision 模型驱动；界面保持简约浅蓝风格。

## 安全与自由选择边界

- 信息不足或硬件可能不兼容：显示警告、降低可信度，但允许继续导出清单、使用自有 EFI 或手动组件路径。
- EFI 结构损坏、组件完整性失败、不安全目录或可能覆盖数据：停止操作。
- 社区机型索引仍是 discovery-only：不自动下载、执行、合并、启用或提高推荐等级。
- 所有融合与复制输出仍写入用户选择的新空目录；工具不分区、不格式化、不下载 Apple Recovery，也不制作完整 macOS 安装盘。

## 验证范围

- 前端/规则层：30 个 Vitest 文件、260 项测试；daliansky 离线目录导入 3 项测试。
- 原生层：Rust 格式与严格 Clippy；61 项普通测试通过，5 项真实网络/WMI 测试在普通测试中保持 ignored。
- 正式 Release 还必须以干净 GitHub Actions checkout 运行 5 项 ignored 集成、构建 NSIS、生成 SHA-256，并在 Windows 上核对签名、安装、启动和卸载。

## 已知限制

- 当前没有代码签名证书，Windows 安装包会显示未知发布者。
- 仍有 23 条兼容规则未迁移到严格案例；合成矩阵不是市场覆盖率，也不是实机成功记录。
- 没有真实 WebView 自动化、目标机启动、Recovery、安装完成、睡眠、USB、无线或音频验证。
- 运行时缓存首版不迁移或清理旧目录；用户需要自行确认旧缓存后再手工处理。
