# EFI Forge 下一轮改进规划

日期：2026-09-06。核查基线：v0.1.14，本地提交 cea8531d37cd810f0651e83da08bd12f1873f907。

## 目标及优先顺序

把“同一硬件得到一致判断、用户能够补全信息、流程失败后能恢复、验证记录可追溯”放在新增型号数量之前。用户可继续使用未知、小众、混搭和自有 EFI；软件不得把候选线索描述为实机成功。

本轮授权给 GPT-5.6 sol 的具体实施范围是工作包 A、B。C—H 是后续路线，先完成设计依赖再逐包实现，不能把整个路线图记作已交付。A、B 可独立验收，不需要引入新依赖、更新组件锁或发布安装包。

| 批次 | 工作包 | 开始条件 | 可交付结果 |
| --- | --- | --- | --- |
| 1 | A、B，纠正判断和证据入口 | 当前代码基线 | 共用分类、显式证据 API、回归结果 |
| 2 | C，让规则审核可追溯 | A 的身份契约稳定 | 可解析案例注册表与规则引用检查 |
| 3 | D，集中流程状态 | 第一批通过检查 | 产物绑定、失效规则、页面拆分 |
| 4 | E，补充信息和用户 EFI 体验 | D 的状态转换可验证 | 可撤销硬件覆盖、清楚的融合差异预览 |
| 4 | F，运行时空间治理 | 缓存原生接口设计完成 | 可选缓存位置、失败恢复、空间提示 |
| 5 | G，扩大配置证据矩阵 | C 已能验证规则案例 | 有来源、正反例和边界的增量硬件规则 |
| 6 | H，交付检查 | 本轮拟发布变更冻结 | GUI 验证记录、安装包及公开状态核验 |

E 与 F 可以分别推进，但凡涉及同一个前端工作流状态，必须统一接入 D 的接口后合并。每批结束交付可运行状态，不以无依据的机型数量或固定工时作为完成标准。

## A：共用硬件身份与设备分类（本轮）

观察：src/engine/deviceIdentity.ts 仅归一一个现有 GPU PCI 身份；src/workflow/hardwareEvidenceSummary.ts 用无线名称正则计数。兼容模块、构建器仍有其他名称判断。src/workflow/buildReadiness.ts 把 name-only 算作弱身份，却漏了 parent-pci。

实施：

1. 盘点 GPU、无线/有线网卡、存储的身份判定消费者，明确哪些已有精确 ID，哪些只是名称线索。
2. 建立轻量共享分类函数，返回类别及识别依据，优先使用直接 PCI；名称只能回退，父 PCI 不作为子设备精确身份。
3. 只复用现有代码已声明的 ID，不根据数字相似性扩展硬件支持。营销名、驱动显示名与分类证据分离。
4. 让硬件摘要和兼容模块使用相同分类；构建判断能安全复用时一并接入。保留特定声卡、混合显卡、NVMe 控制器的细分排除规则。
5. 修复父 PCI 的证据缺口提示，并保留手动继续、自有 EFI 与组件融合入口。

验收：同一已知无线 PCI ID 改名后，摘要与兼容模块仍认作无线；有线设备不因名称含 Wi-Fi 被当作精确无线；未知/名称线索明确标注；parent-pci 显示证据不足；缺口不会改变用户继续权限。

## B：验证证据接口清理（本轮）

观察：observationsForStage 已不使用 stage/result 参数，却仍要求调用者提供；mayPromoteVerification 只依赖已类型化对象，安全性依靠上层先解析。

实施：

1. 用含义明确的观察项初始化函数替换旧接口，仅接收显式观察值，默认均为未测试。
2. 更新 App 与全部调用点，杜绝选择阶段隐含生成通过项。
3. 在验证资格判断入口重新校验结构与阶段观察要求，非法对象应返回否或受控错误，不得升级验证。
4. 保持硬件指纹、BIOS、系统版本、OpenCore、配置哈希绑定规则；保留历史文件，避免静默迁移或改写证据。

验收：空观察项不能生成通过记录；解析后被篡改的证据不能升级；错误或数字系统版本拒绝；不同 BIOS/config 不能绑定；合法显式记录仍能导出及回导。

## C：规则与样本真正关联（下一优先级）

观察：ruleRegistry 当前只检查 testSampleIds 非空；hardwareFixtures 测试验证整机状态，尚不能证明每个声明样本都存在并触发对应规则。

实施：建立独立规则案例注册表，区分合成回归、用户脱敏报告、实机反馈三种来源。每个案例包含稳定 ID、输入、目标系统、预期规则及禁止动作；不强行把现有规则案例 ID 当成整机夹具 ID。校验引用存在、去重、规则实际命中和排除条件。对缺少案例的旧规则逐项补测试，禁止只造空壳案例使检查变绿。

验收：删除案例或拼错引用会失败；每条自动写配置规则有正例、近似反例、缺失身份例；统计分别展示规则命中、证据完整度、实际测试数量，不能输出虚构市场覆盖率。

## D：把 App 工作流拆成可验证的状态转换

观察：App.tsx 同时管理扫描、平台选项、多个 EFI 来源、融合、复制、验证及大量异步 epoch 判断。存在维护复杂度，不能仅凭文件体积认定具体竞态已发生。

实施：先定义硬件输入、计划、操作、产物、验证五类状态及依赖；抽取 reducer 和产物绑定 ID。用户更换硬件、系统或组件后，旧结果必须失效；迟到任务不能覆盖新状态。取消表示停止接纳结果，原生任务是否真正中止需单独实现。再拆分扫描、兼容、组装和交付页面，保留简约浅蓝视觉。不要一次替换整个前端框架。

验收：慢扫描后切换报告、构建时切换系统、重复点击、取消文件选择、融合失败后回退、复制前配置改变都有行为测试；原生文件操作仍重新校验目标与产物。

依赖：A、B 完成后实施；先状态和接口，再页面拆分。

## E：用户补充硬件信息与专属配置闭环

实施：提供可选的厂商、完整型号、机型码、BIOS、PCI/SubSystem 补充界面。保存原始扫描与用户覆盖两份数据，来源明确、可撤销、可导出脱敏报告；用户填写不自动变成扫描证据或实机验证。根据字段变化重新计算计划并使旧产物失效。社区索引未命中仍提供自有 EFI、手动组装路径。

EFI 融合应展示主来源、冲突、补入但未启用、将变更的 config 引用及结果目录；用户可逐项选择，失败保持来源文件不变。

验收：输入校验错误可定位到字段；撤销恢复原扫描；补充前后报告可重现；自动审核资格不因自报身份而虚假提升；输出永远是新目录。

依赖：D 的状态失效机制先落地，避免编辑信息后继续复制旧 EFI。

## F：安装后的缓存位置与空间管理

观察：开发脚本已使用 D 盘，但 builder.rs 的组件缓存与验证器临时目录仍使用系统 temp_dir；安装后的用户没有缓存位置选择。

实施：原生层提供当前路径、可用空间和可选新位置；设置仅作用于应用管理的缓存。使用版本化目录、原子下载、大小/哈希验证、任务锁和中断恢复。迁移采用复制—验证—切换，旧缓存保留至确认；首次实现不附带自动清理磁盘功能。重解析点、目录逃逸、并发下载与缓存被替换必须检查。配置迁移失败可回到旧路径，不能静默覆盖用户文件。

重构切口：先从 builder.rs 抽取共用缓存与受信验证器服务，让组装和自有 EFI 校验调用同一实现；再评估下载、解压、配置生成和安全复制的模块边界。保留 native 层最终校验，不能因前端已有检查而移除。文件行数减少只衡量组织变化，安全行为回归才是验收依据。

验收：磁盘不足、只读路径、断网、进程中断、两次同时下载、错误缓存哈希、中文路径均可恢复；不得移动用户 EFI、Codex 数据或源码。仅报硬件未知不影响手动导出。

依赖：明确原生路径契约和任务并发方式；与 D 的前端任务状态接通。

## G：覆盖老平台和混搭配置的证据矩阵

按风险轴建例子，不按品牌批量声称支持：UEFI/Legacy，老 Intel/现代 Intel/AMD，核显/独显/混合显卡，SATA/NVMe/VMD，USB/CNVi/PCIe 无线，OEM/零售主板，ThinkPad 各系列与 CPU/屏幕/触控板变体。

每个扩充项必须给出精确身份、目标系统范围、官方来源、组件版本与许可、排除条件、固件注意事项和案例。新系统、旧系统或旧组件版本需要同时核查 TypeScript 与 Rust 允许范围，不能只给下拉框加一项。缺乏合法来源的整包仅保留发现链接。实机反馈记录独立于合成样本。

验收：未知型号不会命中所有同系列；相近 PCI 与型号有反例；不适合当前系统的硬件保留手动路径；新增自动模板单独验证产物与同版本 ocvalidate。

第一批矩阵建议如下，表中的预期是工具行为要求，不是机型安装成功声明：

| 场景 | 核心检查 |
| --- | --- |
| Comet Lake，已知核显 PCI，显示名变成 Basic Display Adapter | 已有身份判断保持一致，输出接口仍待校准 |
| Coffee Lake，未知或不在审核范围的主板 | 不把 CPU 代际命中扩展成主板自动配置资格 |
| AMD B450/B550，不同 BIOS 日期或手动固件偏好 | 提示依据明确，用户选择有记录，旧产物失效 |
| Intel 或 AMD 笔记本与类似台式机芯片组名称 | 不套用台式机 AML 和 framebuffer |
| 已知核显、可用独显与高风险独显同时存在 | 全局禁用参数不能误伤用户需要的显卡 |
| ThinkPad T/E/L/P/X 与未知四位机型码 | 可显示相关线索，不误报精确变体，不阻拦自有 EFI |
| Legacy BIOS、旧 CPU 与不同指令集信息 | 手动研究路径明确，不把 UEFI 模板当作 Legacy 安装介质 |
| 同名无线网卡，分别为 PCIe、CNVi 或 USB 来源 | 按真实接口/PCI 证据分层，名称仅作线索 |
| USB 网卡或声卡仅取得父控制器 ID | 不能套用父控制器对应的子设备驱动规则 |
| SATA、NVMe、VMD/RAID 和多个候选安装磁盘 | 控制器与盘型号分开，用户决定目标，工具不切 BIOS 或写分区 |
| 用户提供未知 Kext、AML、Driver 或完整 EFI | 允许扫描和显式选择；损坏内容停止；来源文件不变 |
| 同型号不同 BIOS，或验证后修改 config.plist | 旧实机记录不能绑定新产物 |

每类至少准备正常输入、信息缺失和近似误判案例；没有实际扫描的合成数据必须标注 synthetic，不能填写“已实机验证”。

## H：交互与发布验收

加入真实 DOM/浏览器流程测试，覆盖首次引导、报告导入、警告继续、自有 EFI、冲突选择、验证失败恢复、键盘焦点和窄屏。模拟 native 的测试明确标注模拟；本机扫描、原生构建、安装/卸载、实机启动分别记账。

准备下一版本时同步版本、生成安装包、计算哈希、记录签名状态，使用受控干净环境测试安装/首次启动/卸载。建立源码提交→CI→标签→Release→资产哈希的发布记录。对话中已有发布授权按其范围执行，但不能用预期 URL 当作发布证据。

## 工程边界及完成定义

每个工作包必须交付改动、必要测试、已执行结果和未完成事项。代码审查后的新修改只重跑受影响检查；最终安装包再跑完整 workspace:full。信息不足和兼容风险允许继续，结构/完整性/数据破坏风险停止。不得为了“全绿”降低检查、填造实机结果、替换真实 EFI 或让未知第三方代码执行。

v0.1.14 历史安装包与本轮代码验证是两个不同交付物；只有 v0.1.15 最终干净构建才会包含 A—H 本批修改。
