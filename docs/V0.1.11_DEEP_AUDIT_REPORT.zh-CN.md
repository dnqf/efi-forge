# EFI Forge v0.1.11 深度审计报告

## 审计结论

本报告针对本地 v0.1.11 开发候选。审计目标是确认软件链路在其声明范围内可复验，而不是证明任意硬件能够安装 macOS。最终 GitHub 发布仍须经过干净环境人工安装与真实目标机验证。

## 审计范围

1. Windows 只读硬件扫描、字段脱敏与 CPU 身份。
2. 硬件规则、兼容报告、继续条件与构建路径解析。
3. 官方锁定组件、SHA-256、候选配置生成与同版本 `ocvalidate`。
4. 用户完整 EFI、Kext、AML、UEFI Driver 的扫描、融合和冲突处理。
5. EFI 结构检查、复制资源上限、暂存复验和空目标保护。
6. daliansky 社区索引离线导入、规范化、匹配与 discovery-only 隔离。
7. 桌面端四步流程、浅蓝色界面、窄屏、键盘焦点和用户措辞。
8. 版本、README、发布工作流、候选安装包与哈希追踪。

## 风险模型与强制边界

| 情况 | 行为 |
| --- | --- |
| 硬件信息不足 | 展示缺口和补充方法，允许继续 |
| 硬件可能不兼容 | 降低可信度并高亮风险，允许实验性继续 |
| 社区索引未命中 | 不影响继续权限 |
| EFI 结构或引用损坏 | 停止复制 |
| 锁定组件哈希、许可证或版本不符 | 停止候选构建 |
| `ocvalidate` 未通过 | 不标记为可复制候选 |
| 目标非空、路径重叠、链接/重解析点或资源越界 | 停止复制 |
| 可能分区、格式化或覆盖用户数据 | 当前产品不提供该能力 |

## 本轮发现与修复

### 高优先级

- 修复复制前后存在的状态差：候选先进入暂存目录，复验通过后才移动到目标 `EFI`。
- 将文件数、2 GB 容量和 32 层目录深度限制施加到实际复制过程，避免只依赖预扫描。
- 拒绝配置顶层类型错误、非数组 `Add`、非字典启用项、缺失 Kext `PlistPath` 和重复启用路径。
- 将内部 `readyForInstall` 语义收紧为 `readyForCopy`，避免软件层校验被误解为可安装结论。
- 将清单的硬件来源、采集时间、规则检查、验证阶段与组件许可证/仓库/发布地址带入 Rust 原生边界，并在真正构建前复核；前端展示不可再替代原生授权判断。
- macOS Tahoe 26 即使规则均为部分命中也只允许手动研究路径；篡改清单请求自动配置会被原生端拒绝。

### 中优先级

- 修正 CPU Family/Model 来源并扩充新一代 Intel/AMD 的保守路由。
- 为 Tahoe、现代 NVIDIA、Vega APU、PC711 等补充明确但非阻断的规则。
- 清除最终导出目录中的构建专用 Windows 工具和自动候选临时模板。
- 锁定组件网络请求增加有限重试，并覆盖下载写入、校验、缓存替换失败时的半成品清理。
- 对已有社区快照增加运行时防线，避免仅修导入器后仍展示历史占位链接。
- 硬件报告导入增加字段、数量、唯一性、时间和 CPU 拓扑约束；原生扫描仅缺主板身份时保留其余证据。
- 完整 EFI 的 SMBIOS 身份仅触发通用隐私警告，不在输出中回显具体身份值。
- 补充 Intel 移动 Xeon E-21xx/E-22xx、W-10xxx、W-11xxx，以及 Ryzen 5000 移动 APU、7035 和 Ryzen AI 的保守代际识别；未知型号仍保持未知而非猜测。
- 将清单标量、图形依赖、OpenCore 核心数组、Enabled 类型和组件扩展名纳入原生强制校验，并为每项增加失败先行测试。
- 给所有长耗时工作流加入代次令牌，旧任务完成后不能覆盖用户已经切换的新报告、新选择或新错误状态。

### 用户体验

- 将“规则识别度”和“软件工作流就绪度”分开展示。
- 自动候选与手动组件暂存包使用不同的下一步指引。
- 明确普通文件夹、FAT32 EFI 分区、候选 EFI 和已验证 EFI 的差别。
- 修复窄屏流程导航、交互控件触控尺寸与键盘焦点可见性。

## 仍需人工验证

- 本机专用临时目录已完成静默安装、应用保持运行 5 秒、静默卸载和残留目录检查；仍需在干净 Windows 10/11 x64 复验 SmartScreen 与首次启动。
- SmartScreen 对未签名候选的实际提示；Defender 已完成本机单文件扫描，但仍需在干净环境复验。
- 不同 DPI、窗口缩放、屏幕阅读器与仅键盘完整操作。
- 至少一台 AMD 审核平台、一台 Intel 审核平台和一台手动/社区路径设备的真实 U 盘启动。
- Recovery、安装、声卡、网络、睡眠、USB、显卡加速和系统更新均应分别记录，不能用单一“成功”替代。

## 发布判定

本地软件链路已达到“可供干净 CI 验收的未签名候选”。只有 GitHub CI 的完整 npm 依赖审计、锁定组件下载、真实候选组装和 NSIS 全部通过后，才允许创建 `v0.1.11` 预发布；目标电脑启动证据完成前不得标记为稳定版或宣称普适兼容。
