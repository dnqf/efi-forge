# EFI Forge v0.1.12 Alpha 候选说明

> 状态：Alpha 候选。它是 EFI 生成、检查和安全复制工作台，不是对任意电脑安装成功的保证。

## 本轮目标

v0.1.12 从普通用户、弱网络用户、自定义 EFI 用户、旧硬件研究者、键盘/读屏用户、维护者和发布者视角收紧完整链路。硬件信息不足和兼容风险仍只产生警告；EFI 结构损坏、组件完整性失败、不可移植路径和可能覆盖数据仍会停止。

## 新增与改进

- EFI 和用户组件在校验、融合或复制前新增 Windows/FAT32 文件名门禁：拒绝保留设备名、尾随空格/句点、控制字符、不安全字符和同目录大小写碰撞。
- 组件下载失败会说明是否存在已验证缓存、现有缓存是否因大小/SHA-256 不合格被拒绝，并给出系统时间、代理、防火墙和 GitHub 连接检查方向。
- 文件、结构、目标位置、权限和网络错误保留原始错误，同时显示一条对应的恢复动作；不会建议绕过哈希或改用未知镜像。
- 四步工作流新增键盘焦点迁移和读屏实时状态，流程跳转后会落在新步骤标题。
- 完整 EFI 校验后可导出“转移 / 求助摘要”，包含硬件型号、风险计数、候选资料、验证级别和 config SHA-256；不包含本机文件路径、序列号或网络凭据。
- 新增统一版本同步检查，覆盖 package、package-lock、Cargo、Cargo.lock、Tauri 配置以及前端显示版本，CI 与候选构建使用同一脚本。

## 不变的边界

- 社区仓库与 daliansky 机型索引仍只是未审核发现线索，不参与自动 BuildPlan、下载、合并或可信度推荐。
- 未收录、小众、混搭和旧硬件不会被禁止使用；工具会展示证据缺口并保留完整 EFI、单组件和手动配置路线。
- 自定义 EFI 只做静态检查；不会执行其中的工具、脚本或二进制。
- 只向新目录或用户明确选择的空目标复制，不分区、不格式化、不覆盖已有数据。
- `ocvalidate` 通过不等于真机可启动；仍需独立 U 盘依次验证 Picker、Recovery、安装和安装后功能。
- Windows 安装包暂未进行 Authenticode 签名，用户应以 Release 页 SHA-256 为准。

## 候选验收门槛

- 版本同步、npm 依赖审计、前端单元测试、社区目录测试、TypeScript 和生产构建通过；
- Rust 格式、严格 Clippy、普通测试、Windows WMI 测试、锁定组件下载与真实候选组装测试通过；
- Windows x64 NSIS 构建、SHA-256、Defender 扫描、静默安装、启动和卸载复验通过；
- GitHub clean-checkout CI 与 release-candidate 工作流全部成功后才创建预发布。
