# EFI Forge 阶段 2–6 进度报告

## 本轮已落地

### 阶段 2：数据驱动规则注册表

- 每条兼容规则现在绑定显式优先级、输入证据、成熟度、结构化操作、来源和测试样本 ID。
- 规则注册表有独立结构校验，重复/非法 ID、非 HTTPS 来源、缺少证据和测试绑定都会使测试失败。
- 匹配引擎按优先级和证据精度决策，不再依赖数组顺序；组件与启动参数开始由规则操作传递到构建计划。

### 阶段 3：模块化适配矩阵

- 兼容报告新增 CPU/芯片组、图形、有线、无线、音频、存储、USB、笔记本输入、电池、背光和睡眠 11 个模块。
- 混合显卡和风险存储产生用户可见的候选分支。
- 明确不兼容独显可由用户选择禁用或完整保留；未知独显不会被工具静默禁用。

### EFI 安全融合工作台

- 用户可选择“项目生成 EFI 优先”或“用户 EFI 优先”。
- 两份源 EFI 永不修改；融合只写入新暂存目录。
- 次来源只补齐缺失文件，同名冲突保留主来源。
- 补入但未被主 `config.plist` 引用的 ACPI/Kext/Driver 标记为“仅保留、未启用”。
- 符号链接、Windows 重解析点及 `.exe/.bat/.cmd/.ps1/.vbs/.msi/.scr` 等载荷会停止融合。
- 融合结果结构或启用引用损坏时删除本次新暂存目录，不产生可安装输出。

### 通用单独组件交换台（第一批）

- 可只读选择 Kext 目录、AML、x86_64 UEFI Driver 或包含这些组件的普通目录。
- Kext 解析 `Info.plist`、Bundle ID、版本、声明的可执行文件和依赖；AML 校验 ACPI 表头、长度和校验和；Driver 校验 PE32+、x86_64 与 EFI 子系统。
- 每项显示逻辑身份、SHA-256、大小、项目候选中的对应关系和风险警告。
- 用户可逐项保留项目版本、使用导入版本、补入但不启用、隔离保留或跳过。
- 原始 EFI 与用户组件都不修改；结果始终写入新目录，并附带组件报告、来源报告和首读说明。
- 融合前后锁定 `config.plist` 哈希；替换已启用 Kext 后还会复查 `ExecutablePath` 与 `PlistPath`。
- 复制后重新计算目标组件哈希；来源在扫描后变化、复制不一致或最终引用损坏时停止并清理暂存目录。

### 受控配置条目生成器

- 新组件默认仍为“补入但不启用”；只有用户逐项选择“加入并写入配置”才会修改新副本。
- Kext 生成最小 `Kernel/Add` 条目，AML 生成最小 `ACPI/Add` 条目，Driver 生成最小 `UEFI/Drivers` 条目。
- Kext 的 `ExecutablePath` 和 `PlistPath` 必须与包内声明一致；非 Apple 依赖必须全部已启用。
- 所有启用 Kext 按依赖关系稳定排序；缺少依赖、重复 Bundle ID 或循环依赖会停止。
- 每次配置写入记录修改前后 SHA-256，并保护 PlatformInfo、DeviceProperties、NVRAM、Kernel Patch、Emulate 和 Quirks 不被改变。
- 配置或已启用组件变化后，从 SHA-256 锁定的 OpenCore 官方压缩包临时提取 `ocvalidate`；不会执行用户 EFI 携带的验证程序。

## 阶段 4–6 的安全骨架

### 阶段 4：社区来源准入

- 新增社区条目准入校验：GitHub HTTPS 来源、40 位固定 commit、许可证、厂商/完整型号/CPU、BIOS 范围、验证日期和安全审核门。
- `verified` 条目必须声明已清除身份、拒绝未知程序、替换为官方锁定二进制；否则不能进入精确匹配。
- 当前生产社区注册表仍为空，因此软件不会宣传已内置社区整包。

### 阶段 5：真机证据绑定

- 新增真机验证证据解析与绑定检查。
- `boot-tested`、`recovery-tested`、`install-verified`、`post-install-verified` 必须绑定完全一致的硬件指纹、BIOS、macOS、OpenCore 和 `config.plist` SHA-256。
- 失败证据或任一绑定不一致均不能提升验证等级。

### 阶段 6：旧平台分流

- 现代 UEFI、旧平台手动 UEFI、Legacy/OpenDuet 实验、CPU 指令集风险已分为独立路径。
- Legacy/OpenDuet 不进入现代自动配置；仍允许用户导出研究清单或使用自有 EFI。
- 已明确报告缺少 SSE4.2 时停止自动生成，但不删除用户的手动选择权。

## 尚未完成，不能对外宣称

- 尚未实现社区仓库的联网拉取、自动身份清除和官方二进制替换流水线。
- 尚未在界面中导入 OpenCore 启动日志和真机证据文件。
- 旧平台尚未生成 OpenDuet 可启动介质，也没有旧平台真机验证。
- 融合只保证静态结构与引用完整，不会自动理解或启用陌生 ACPI/Kext/Driver。
- 受控生成器只负责最小条目和 Kext 依赖顺序，不判断陌生 ACPI/Driver 的机型语义，不生成 DeviceProperties、启动参数或专属 Quirks。
- 没有新增任何 Recovery、安装或安装后功能成功证据。
