# EFI Forge 通用组件选择与安全融合 Codex 实施提示词

## 角色与任务

你是 EFI Forge 的主工程代理。当前产品是 `v0.1.6 alpha` 的 Windows/Tauri OpenCore 候选配置工作台，不是已经覆盖多数电脑的一键安装器。

本轮只实施“通用 EFI 组件选择与文件级安全融合”第一批能力：允许用户把项目生成 EFI、用户完整 EFI和单独组件包放入同一工作台，查看静态身份与差异，逐项选择后输出新的融合副本。

不得把规划、静态检查或 `ocvalidate` 描述成真机启动、Recovery、安装或安装后验证。

## 用户原则

1. 最大限度保留用户选择权。
2. 信息不足、来源未知、版本较旧或硬件可能不兼容时只警告，不阻止用户继续。
3. EFI 结构损坏、启用引用缺失、危险载荷、路径穿越、符号链接、Windows 重解析点或可能覆盖用户数据时必须停止。
4. 永远不修改项目生成 EFI、用户 EFI 或导入组件源目录。
5. 所有融合结果写入用户选择位置下的新目录。

## 本轮必须交付

### 1. 通用只读导入

支持选择：

- 单个或多个 `.aml` 文件；
- 单个或多个 `.efi` Driver；
- 单个 `.kext` 目录；
- 包含 Kext、AML、Driver 的普通目录。

导入后生成内存中的扫描会话；后续融合只能引用该会话中已由原生后端确认的文件，不能信任前端提交任意本地路径。

### 2. 静态身份与安全检查

每个组件至少记录：

- 稳定项目内 ID；
- 类型、显示名称和建议目标路径；
- SHA-256、大小、版本、逻辑身份；
- 与项目候选 EFI 的关系：新增、完全相同、同路径冲突或同逻辑身份冲突；
- 默认动作、允许动作、来源等级和警告。

Kext 必须解析 `Contents/Info.plist`，读取 `CFBundleIdentifier`、版本、可执行文件和依赖；声明的可执行文件必须存在且位于包内。

AML 必须检查 ACPI 表头、声明长度和校验和，不能只信任扩展名。

Driver 必须检查 DOS/PE 签名、x86_64 机器类型、PE32+ 和 EFI 子系统，不能只信任扩展名。

递归扫描必须限制文件数量、总大小和目录深度；拒绝符号链接、重解析点、路径穿越及 `.exe/.com/.bat/.cmd/.ps1/.vbs/.js/.msi/.scr` 等 Windows 载荷。不得执行导入目录中的任何文件。

### 3. 用户逐项选择

首版动作：

- `keep-base`：保留项目候选中的版本；
- `use-imported`：在新融合副本中用用户组件替换同目标项目组件；
- `add-inactive`：补入新组件但不修改 `config.plist`；
- `preserve-inactive`：冲突组件以隔离名称额外保留，不启用；
- `skip`：不加入。

默认使用项目锁定组件；用户可以明确改选未经审核的版本，界面必须显示来源和风险。

### 4. 文件级融合输出

从结构完整的基础 EFI 复制到新暂存目录，再应用用户选择。不得在本轮自动修改 `config.plist`。

输出至少包含：

```text
EFI-Forge-Component-Merged/
├─ EFI/
├─ EFI-FORGE-COMPONENT-REPORT.json
├─ EFI-FORGE-PROVENANCE.json
└─ README-FIRST.txt
```

报告必须记录每项选择、来源哈希、最终目标、是否启用以及警告。融合完成后重新运行 EFI 结构与启用引用检查；失败时只清理本次新建暂存目录。

### 5. 界面

在 EFI 组装页使用 A/B/C 三来源语义：

- A：项目生成候选 EFI；
- B：用户完整 EFI；
- C：用户单独组件包。

组件交换台显示类型、身份、项目状态、用户哈希、警告和动作选择。动作名称必须从用户视角描述，不使用后端术语。键盘焦点、窄屏布局和禁用原因必须清晰。

## 本轮禁止实现

- 不自动合并整份 `config.plist`；
- 不修改 `PlatformInfo`、`DeviceProperties`、NVRAM、Kernel Patch 或 Quirks；
- 不猜测陌生 Kext 的配置条目、加载顺序或启动参数；
- 不联网搜索或自动下载用户组件；
- 不把未知社区组件提升为项目推荐；
- 不格式化磁盘、不覆盖非空目标、不执行用户程序。

## 测试与验收

修改前先增加失败测试，至少覆盖：

1. 合法 Kext、AML、x86_64 UEFI Driver 的识别；
2. 损坏 AML、伪装 `.efi`、Kext 缺失 `Info.plist`/可执行文件；
3. 符号链接、重解析点、危险扩展名、超限目录；
4. 相同哈希、同路径不同哈希、同 Bundle ID 不同目录；
5. 所有用户动作及默认动作；
6. 原始来源始终未修改；
7. 输出结构损坏时不会留下可安装目录；
8. 不会修改融合输出中的 `config.plist`；
9. 前端选择变化会使旧融合结果失效；
10. 中文路径和空目录。

完成后必须运行：

```text
npm test
npm run build
cargo test
cargo fmt --check
cargo clippy --all-targets -- -D warnings
npm run desktop:check
git diff --check
```

联网下载测试保持默认忽略。没有新增真机证据时，最终报告必须继续标记为结构候选或实验结果。
