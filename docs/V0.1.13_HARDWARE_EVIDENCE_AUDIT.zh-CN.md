# EFI Forge v0.1.13 Alpha · Hardware Evidence 2.0 审计记录

本记录对应 2026-09-03 完成的 v0.1.13 全链路工作树复验。它替代基线提交 `13fe3ef5f8cac7abc7fabc20f20d0a1d62d124c9` 的旧候选结果；发布标签必须指向包含本记录与修复代码的最终提交。这里记录的是可重复的工程验证，不代表任何目标电脑已经完成 OpenCore、Recovery、macOS 安装或长期稳定性验证。

## 本轮修复

- 修复 DSDT 静态分析成功后任务纪元变化导致界面持续显示“处理中”的状态锁。
- 切换硬件、macOS、OpenCore 或 `config.plist` 哈希时清空旧的真机验证表单，避免观察记录误绑到新 EFI。
- Hardware Evidence 2.0 控制器、固件、Secure Boot、CPU 线程与笔记本线索全部进入验证绑定键。
- GPU、网络、音频和存储缺失时产生明确检查项，不再缩小规则覆盖度分母。
- AMD 可用独显与不兼容独显混搭时拒绝全局 `-wegnoegpu`，改为设备级人工处理提示；Intel 核显混搭仍保留用户选择。
- 旧 ThinkPad 保持机型专项路由；T480/T480s/X1C6/T490/X1C7 与原生扫描器的 `kaby-lake-r` 分类一致。
- ThinkPad 存储风险与全局 PM981/PM991、Micron 2200S、SK hynix PC711、Optane/3D XPoint 规则一致。
- 导入报告拒绝跨分组重复 ID、相互矛盾的 Subsystem ID；社区审核日期验证真实日历日期。
- 固定测试样本在流程栏明确标记为“样本预览”；README 恢复为真实公开最新版 v0.1.12，避免提前发布无效链接。

## 已知限制

1. Hardware Evidence 2.0 提供控制器和设备线索，仍可能因固件隐藏、WMI 缺失、热插拔或厂商自定义 ACPI 而不完整。
2. 原生扫描器中的父 PCI 字段为可选信息；导入的 schema v2 报告可以携带它，但缺失时只产生警告。
3. 社区机型索引（包括 daliansky/Hackintosh）仍是 discovery-only 账本，不自动下载、合并或提升可信度。
4. `ocvalidate` 或结构校验通过只代表静态结构有效，不等于在具体硬件上能够启动。
5. 未在本轮执行真实目标 Mac 的 Picker、Recovery、安装和外设长期稳定性验证。
6. 安装包未签名；用户应从 GitHub 官方 Release 下载并核对 SHA-256。
