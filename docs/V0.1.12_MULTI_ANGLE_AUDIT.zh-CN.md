# EFI Forge v0.1.12 多角度审计记录

## 审计结论

本轮优先修补能够由软件测试证明的链路，不用新增型号数量制造虚假覆盖。自动配置仍只限已审核平台；旧硬件、小众设备和混搭组合通过证据缺口、社区发现与用户 EFI 路径继续研究。

## 使用角度与处置

| 角度 | 发现的风险 | v0.1.12 处置 |
| --- | --- | --- |
| 第一次使用 | 跳转后不清楚当前处于哪一步 | 聚焦新步骤标题，并通过 live region 宣布状态 |
| 弱网络 | 只知道下载失败，不知道缓存是否可用 | 区分已验证缓存、被拒绝缓存与无缓存，保留三次重试和哈希门禁 |
| 自定义 EFI | NTFS 上可见的名称不一定可安全复制到 FAT32 | 在扫描、校验和复制前统一检查可移植文件名与大小写碰撞 |
| 无法在当前电脑安装 | 需要把最小诊断信息带到另一台电脑或论坛 | 导出不含本机路径/序列号的转移与求助摘要 |
| 旧硬件与小众组合 | 无自动模板时容易误解为工具不可用 | 保留手动组件、完整 EFI、社区发现和证据补充路线，不降低继续权限 |
| 数据安全 | 错误恢复可能诱导用户绕过校验或覆盖目标 | 恢复提示明确要求空目录、独立测试盘和不绕过 SHA-256 |
| 维护者 | 多处版本号可能漂移 | 单一脚本校验七处版本表现，并进入 CI 与候选工作流 |
| 发布者 | 本地成功可能掩盖干净环境失败 | 继续要求 clean-checkout CI、真实锁定组件测试和 NSIS 候选复验 |

## 可证明与不可证明

软件可以证明：报告结构、规则命中、锁定组件身份、SHA-256、EFI 静态结构、配置引用、路径安全、空目录复制和证据绑定。

软件不能在没有对应真机的情况下证明：固件设置正确、OpenCore 可启动、Recovery 可用、安装完成，以及显卡、无线、音频、USB、睡眠和电源管理全部正常。因此 Release 必须保持 Alpha / prerelease，不宣称“全机型一键安装”。

## 三轮复验计划

1. 本地快速门禁：版本同步、前端与 Rust 单元测试、目录测试、TypeScript、生产构建、格式和严格 Clippy。
2. 本地真实链路：锁定组件下载、AMD/Intel 真实候选组装、WMI 扫描、NSIS 构建与安装生命周期。
3. GitHub 干净环境：常规 CI、候选工作流、产物哈希、签名状态、Defender 与独立安装复验。

最终数据在候选产物完成后补入 Release 元数据和 GitHub 工作流记录；任何失败都必须先修复并重新从对应轮次开始。
