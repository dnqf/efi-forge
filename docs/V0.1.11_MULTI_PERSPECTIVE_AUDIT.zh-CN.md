# EFI Forge v0.1.11 多视角复核

## 结论

v0.1.11 已达到“可供人工验收的本地未签名候选”，但没有被描述为普适的一键黑苹果安装器。软件能自动证明的是输入、组件、配置结构、复制边界与来源追踪；真机启动、Recovery、安装和安装后功能仍必须由目标电脑逐级验证。

## 普通用户视角

- 将规则识别度与成功率分离，避免把 80% 规则命中误解为 80% 安装概率。
- 信息不足、社区索引未命中和硬件兼容性存疑只产生警告；结构损坏、哈希失败和数据覆盖风险才停止。
- 流程明确提供项目候选、用户完整 EFI、单组件补充/替换三种起点，并把高级融合保持为显式选择。
- 第 4 步区分“导出到普通空目录”和“复制到已挂载 FAT32 EFI 分区”，不暗示软件会分区或制作 macOS 安装盘。

## 旧平台与混搭硬件视角

- CPU、GPU、网络、音频、存储和固件分别给出证据，不使用单一机型名称掩盖混搭风险。
- 新增 Kaby Lake-R、Intel 移动 Xeon、Ryzen 5000/6000/7000/8000/9000 与 Ryzen AI 常见命名识别，以及 Vega 7、现代 NVIDIA 与旧式 UEFI/Legacy 路由。
- Tahoe 26 只进入研究性手动路径；不存在自动配置承诺。
- 未知 ThinkPad 和社区索引未命中不阻止用户导入专属 EFI，但也不提升可信度。

## 安全与隐私视角

- 硬件报告导入受长度、数量、唯一性、时间和 CPU 拓扑约束，异常输入不会直接进入工作流。
- 原生构建端复核清单来源、硬件键、验证阶段、必需闸门及组件来源/许可证/SHA-256，不能只靠前端按钮状态授权构建。
- 用户 EFI 不会被执行；符号链接、重解析点、特殊文件、Windows 可执行载荷、资源越界与错误引用类型会被拒绝。
- SMBIOS 身份只触发不回显具体值的警告；应用默认无账号、遥测或后台上传。
- 复制只写入用户选择的空目录，采用暂存、复验、再提交的顺序，不覆盖已有 EFI。

## 维护者与供应链视角

- OpenCore、Kext、ACPI 与工具资产由锁文件限定版本、URL、大小、SHA-256、仓库和许可证。
- daliansky/Hackintosh 只作为固定提交的离线发现索引，不自动克隆、下载、合并或推荐其中 EFI。
- 常规 CI 与候选 CI 均把外部 Actions 固定到完整 commit SHA，并固定 Rust 1.98.0；候选 CI 还检查版本同步、前端、TypeScript、完整 npm 依赖审计、Rust format/Clippy/test、真实锁定组件与 WMI，再生成安装包、哈希和元数据。Dependabot 只负责提醒维护者审查升级。
- 本地候选与 GitHub Release 明确分层；本地哈希不能被沿用为未来 CI 资产哈希。

## 测试与可访问性视角

- 固定硬件矩阵覆盖可构建、手动、未知、混搭与阻止路径，但只验证规则决策。
- 桌面与窄窗口完成浏览器视觉复核；流程导航、焦点样式和触控尺寸已有响应式处理。
- 当前本地结果：15 个前端测试文件共 124 项、3 项目录导入测试、52 项 Rust 普通测试、4/5 项真实链路测试、严格 Clippy、格式、TypeScript、Vite 与 NSIS 通过。剩余锁定组件下载因本机对 GitHub 的 TLS 握手失败，必须由干净 GitHub CI 重新判定，不能在本地写成通过。
- 最终 NSIS 已在专用临时目录完成静默安装、5 秒启动存活、静默卸载和目录清理，并通过 Microsoft Defender 单文件扫描。

## 仍不能自动证明的事项

1. 干净 Windows 10/11 环境中的安装、首次启动、卸载和 SmartScreen 行为。
2. 真实目标电脑的 BIOS 设置、USB 映射、ACPI 语义、核显 framebuffer、睡眠、音频、网络和系统更新。
3. OpenCore Picker、Recovery、macOS 安装、桌面与安装后各阶段的实机结果。
4. 未签名安装包的发布者信誉；正式公开前应继续考虑 Authenticode 签名。

因此，下一道门不是扩大宣传，而是在干净 Windows 环境和多台目标硬件上积累与精确硬件、BIOS、OpenCore 版本和 `config.plist` 哈希绑定的验证证据。
